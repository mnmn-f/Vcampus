# VCampus UI 规范

本文定义面向学生、教师和各类管理人员的 Swing 桌面界面规范。页面上的文字只服务于实际使用者；实现、数据库和验收说明分别记录在 [架构说明](ARCHITECTURE.md) 与 [需求追踪矩阵](REQUIREMENT_TRACEABILITY.md) 中。

## 设计依据

信息架构参考 [seu-vcampus](https://github.com/zeroffa233/seu-vcampus) 的校园门户做法：品牌区与侧栏导航固定在左侧，内容区使用白色卡片，主导航按人员职责收敛，页面内再用二级任务切换。VCampus 用 Java Swing 和自绘线性图标实现同样的层次关系；角色、权限和数据范围仍以本项目的会话与服务端校验为准。

设计取舍遵循三个原则：

- 登录成功后按服务端返回的职责展示对应主页标题、快捷入口和侧栏，不把所有人员放进同一套业务菜单。
- 先展示任务入口，再展开数据。主导航负责模块，模块页用页签承载查询、维护、审批、日志等二级任务，避免把所有面板纵向堆在一个长页面中。
- 让状态和下一步可见。加载、空结果、成功、警告和错误都使用文字说明；高风险操作在确认后提交，最终权限判断由服务端完成。

## 尺度与字体

- 基础间距为 4px，优先使用 8、12、16、24、32px。
- 页面标题 24px，卡片标题 16px，正文 14px，辅助说明 12px；主要字重使用 Regular 与 Medium 两档。
- 优先使用 `Microsoft YaHei UI`，不可用时回退到 Java 无衬线字体。
- 卡片使用白底、细边框、10px 圆角；内容区使用浅灰绿背景，主内容保持清晰留白。
- 预览与验收至少覆盖 1100×720 和 1280×820；表格、筛选区和操作区在较小窗口中仍应保持可读，超出时由页面滚动承载。

## 登录与人员分流

登录页只提供校园账号、学号或工号输入框、密码输入框和登录按钮，不提供人员、身份或角色选择。客户端将登录标识和密码一次封装为请求；服务端统一匹配 `users.username`、`student_profiles.student_no` 和 `teacher_profiles.employee_no`，校验通过后返回姓名、用户编号和有效职责。显式预览模式也使用同一两字段表单，不在页面上列出账号或人员选项。

登录后：

- 当前职责来自登录结果，决定工作台标题、快捷操作和侧栏可见模块；姓名、校园账号和用户编号在顶部身份区显示。
- 只有同一账号拥有多个职责时，顶部才显示“切换工作身份”；切换后重新刷新导航和页面权限上下文。
- 所有人员都有“个人中心”，用于查看本人资料、修改密码和处理本人注销申请；管理审批不放在个人入口中。
- 角色不可见的模块不以灰色按钮或空白占位留在侧栏中，避免把无权操作误认为可用功能。

当前职责入口如下：

| 职责 | 主页定位 | 主要侧栏入口 |
|---|---|---|
| 学生 | 学生主页 | 我的学籍、选课与课表、图书馆、校园商店、宿舍生活 |
| 任课教师 | 教师主页 | 我的教学、图书馆 |
| 学籍管理员 | 学籍工作台 | 学籍管理 |
| 教务老师 | 教务工作台 | 教务管理 |
| 图书管理员 | 图书馆工作台 | 馆务管理 |
| 商店管理员 | 商店工作台 | 商店运营 |
| 宿管员 | 宿管工作台 | 宿舍管理 |
| AI 知识管理员 | 知识服务工作台 | 安全与运行 |
| 系统管理员 | 系统管理工作台 | 账号与角色、安全与运行 |

以上是界面入口分流；每个业务命令仍由服务端依据 `activeRole`、`userId` 和细粒度权限再次判断。

## 外壳与导航

登录后的 [AppShell.java](../vcampus-client/src/main/java/edu/seu/vcampus/client/view/AppShell.java) 固定为三层：

1. 左侧品牌与侧栏：显示 VCampus、东南大学校园服务、当前职责和按角色过滤的主导航；选中项使用主色和金色细线强调。
2. 顶部栏：显示当前页面标题、姓名、当前工作身份和退出登录；多职责账号才显示角色切换器。
3. 内容区：页面标题、简短任务说明、快捷操作或任务页签，以及可滚动的业务内容。

侧栏分为“我的工作台”“校园业务”“系统管理”三组。主页快捷卡片只链接到当前职责可用的任务，不展示其他角色的操作。

### 小松鼠桌宠

- 仅当当前职责可进入 `AI_ASSISTANT` 时显示；正常展开时默认悬浮在主界面右下角，可在分层面板内自由拖动并保存位置，不挤压聊天框或其他页面布局。
- 形象使用透明背景的软萌 3D 松鼠：橘红毛色、超大黑眼睛、蓝色上衣、红色书本和大尾巴；基础图位于 `vcampus-client/src/main/resources/edu/seu/vcampus/client/pet/squirrel.png`，六姿势动作表位于同目录的 `squirrel-actions.png`。
- 动作包括待机呼吸、悬停招手、思考歪头、回答摆手、待确认提醒、成功跳跃和失败低落；回答与悬停使用循环切帧，其余姿势使用平滑位移、缩放、倾斜和阴影补间。
- 正常界面单击松鼠进入校园助手；若已经位于 AI 页面，只播放短回应动画。
- 最小化后隐藏主窗口并显示置顶桌面松鼠；拖动超过 5 像素只移动，单击恢复原页面和原窗口状态。主窗口和桌面形态右键均可喂松果、抚摸；桌面形态另提供“展开主界面”和“打开校园助手”。
- 气泡使用固定短文案，不显示用户问题、模型回答或敏感业务内容。颜色继续使用橄榄绿主色、金色点缀和现有成功/警告/错误语义色。
- 不支持逐像素透明的桌面环境降级为普通无边框小窗；`vcampus.pet.animation=false` 时关闭循环切帧和补间动画，但保留状态姿势及全部入口行为。

### AI 对话输入区

- 页面不再重复显示“校园助手对话”标题；会话侧栏每次进入时默认折叠，展开后可搜索、重命名、归档、查看已归档会话并恢复。生成期间禁止新建、切换或加载其他会话，避免流式内容串入错误会话。
- 对话区使用气泡布局：用户消息靠右，助手回复靠左，宽度随内容收缩并设置合理上限；点赞、点踩和纠错入口附着在对应助手气泡上，不使用会话级统一按钮。
- 输入区上方按问答、聊天、代办模式显示可横向滚动的示例按钮，示例优先选择现有知识或工具可以稳定完成的问题；问句末尾有无中文标点均应命中相同意图。
- Enter 发送，Shift+Enter 换行。聊天模式输入框左侧显示“+”，可添加最多 3 个图片、PDF、DOCX、PPTX、XLS/XLSX、CSV、文本或代码附件；办公文档在客户端提取文字，切换到问答或代办模式会清空附件。附件卡片显示环形上传进度，全部加载完成前发送按钮不可用。
- 模型回答按纯文本展示，过滤 Markdown 星号、方框、反引号和数字引用标记；业务查询结果使用中文字段、简短日期时间和分段条目，不展开 Java 内部对象。
- 代办参数不足时先显示结构化澄清问题，不弹业务确认；日期时间参数使用日期/时间选择控件，自习室预约同时提供自习室编号输入。参数齐全后才进入二次确认。
- 失败气泡的“重试”复用原 `requestId` 和同一次逻辑请求，直接替换失败回复，不新增重复用户消息；含附件的首次请求等待附件准备完成后发送。

### AI 知识管理员工作台

- 工作台按七个任务页签组织：知识库管理、知识测试、批量回归、用户反馈、路由测试、工具状态和运行监控。
- 知识库列表提供服务端分页。文档导入先展示可编辑分段，支持去重和选择性导入；确认后单次事务提交，失败时整体回滚并保留预览内容供修正。
- 知识测试除问题外可填写标准答案和预期命中知识；批量回归集中展示每题命中与答案结果，便于知识更新前后复测。
- 用户反馈可按点赞/点踩、问题类型、时间和待处理/已处理/忽略状态筛选；表格选中后可点击“查看完整信息”或双击行，在可滚动详情中查看完整摘要、补充说明和精确时间，处理时可关联并跳转到知识片段。
- 路由测试只展示意图、工具和参数解析结果，不执行校园工具；工具状态展示最近调用时间、成功率、平均耗时和最近错误。

## 页面结构

真实模块页统一由 `BasePage`、`TaskTabs` 和 `SectionCard` 组合：

- 页面头部：职责化标题和必要的主操作。
- `TaskTabs`：把同一模块中的查询、维护、审批、日志等任务放在二级页签内，选中页签使用主色背景和白色文字。
- 筛选与工具栏：标签清楚、控件顺序符合查询流程，查询条件留在结果上方；分页和结果范围在同一区域可见。
- `SectionCard`：白色圆角卡片承载表单、表格或详情，卡片之间保留 16–24px 间距。
- 状态反馈：字段错误紧邻字段；页面级错误位于当前任务区；成功提示轻量显示并在刷新后消失。

表格列应优先使用稳定编号、中文状态和可读日期；数值右对齐，空值显示 `—`，操作列不换行。枚举 code 在展示层映射为中文，提交时仍传稳定 code。列表无数据时说明原因并给出查询、创建或返回入口。

## 交互与高风险操作

- 查询、分页、普通新增和编辑不弹模态确认；操作结果在当前任务区反馈。
- 删除、付款、退选、取消订单、撤回申请、归还、审批驳回、强制下线、角色撤销等会改变状态或造成不可逆影响的动作必须先确认。
- 付款、库存、余额、账号状态、会话状态等不由客户端自行判定；客户端只做即时输入校验，服务端负责权限、状态机、事务和并发校验。
- 长耗时操作显示加载状态并暂时避免重复提交；网络断开或超时使用面向用户的错误说明，不展示技术堆栈、协议对象或数据库名称。
- 显式预览模式不提供静态业务数据或伪操作按钮；网络页面不填充虚构业务数字，暂无数据使用 `—` 或空状态说明。

## 验收清单

- 以至少两个不同职责登录，侧栏、主页标题、快捷入口和可见模块均不同。
- 以多职责账号切换当前工作身份，确认导航和页面标题随身份变化。
- 在 1100×720 与 1280×820 预览中检查无标题遮挡、控件重叠、横向溢出和不可见的主要操作。
- 检查成功、空结果、输入错误、权限错误、超时和高风险确认均在当前任务区表达。
- 对照 [UI_PREVIEW_GALLERY.md](UI_PREVIEW_GALLERY.md) 和 [PAGE_MAP.md](PAGE_MAP.md) 验证截图入口与实际职责一致。
- 验证有/无 AI 权限职责的桌宠可见性；检查窗口内拖动阈值、边界校正和位置持久化；分别从正常和最大化状态最小化，检查桌面位置独立保存、右键入口、跨屏校正、页面保留和恢复状态。
