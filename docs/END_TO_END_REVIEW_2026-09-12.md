## 本轮修复

| 发现的问题 | 处理与证据 |
| --- | --- |
| 缩小窗口后按钮换行却被裁切，页面仍被宽内容撑开 | 公共工具栏采用真实换行高度；页面复用 `WidthTrackingPanel`；卡片允许横向收缩。宽表保留自身横向滚动。`BasePageResponsiveTest` 覆盖 800/960/1280 宽度，工具栏测试覆盖 360/560/800。 |
| 部分动态表格仍能拖动列头 | `TableInteractionPolicy` 在公共页面递归安装，也处理后来加入的表格和表头替换。全角色结构测试检查按钮事件及列头锁定。 |
| 刷新清空选中项、旧响应覆盖新结果、排序后操作错行 | 分页表格按稳定键恢复选中项，转换视图/模型行号，抑制替换期间的中间回调；保留请求序号隔离；手动加载失败清除旧操作目标。 |
| 别的客户端改动后必须退出模块才看见 | 可见通用列表、购物车、账户及图书等已接入页面采用约 8 秒轮询；页面隐藏或正在编辑时暂停。订单详情和选择状态随新结果更新。 |
| 商品图片不显示、图片加载拖慢业务查询 | 商品列表增加缩略图列；图片允许有限 HTTP 重定向、保持比例、有缓存和大小/像素限制；使用独立有界下载线程池，不占用业务查询任务队列。 |
| 购物车移除后重新加入不更新，慢请求恢复旧商品 | 请求序号隔离旧读取；写操作期间禁用重复操作；成功后使用返回的最新购物车。覆盖重复点击、移除后再加入及延迟响应。 |
| 订单详情返回顺序与当前选择不一致 | 详情回调校验当前订单；更新支付按钮状态。真实 TCP 三连接测试覆盖同账号购物车、重复支付不双扣、管理员物流更新后学生读取。 |
| 分类、促销、优惠券搜索框没有真正筛选 | 复用 `PageSlice.filter` 做名称/编码筛选及分页。分类和促销可明确进入新建状态，分类编辑保持编码稳定。 |
| 编辑促销意外改掉生效时间和叠加设置 | 更新已有规则时保留服务端原有时间区间及叠加设置；新增规则仍使用既有默认设置。 |
| 优惠券过期仍呈现可领取、连续点击重复发送 | 显示已过期并禁用领取；领取期间锁定提交；领取后刷新最新状态。服务端仍是最终校验者。 |
| 宿舍空间维护下拉加载失败 | 原请求每页 200/500 条超过服务端上限；改为每页 100 条逐页加载。测试使用 251 条引用数据，失败时不再静默显示空选项。 |
| 学生门禁登记可以伪造登记时间和来源 | 学生时间统一由服务端生成、来源固定为 SELF；管理操作仍保留合法历史登记能力，方向先校验。 |
| 自习室改时段后旧选择仍能提交 | 日期/楼层/起止时段变化时重查并清空旧选择；反向时间段在发请求前提示。 |
| 学籍编辑控件巨大、已有目录值不在下拉时丢失 | 保存按钮使用紧凑操作行；已有档案的有效目录值在回填时保留，不要求输入数据库用户编号。 |

## 尚不能由本轮结果保证的部分

- 多客户端测试在本机建立真实独立 TCP 连接，不等于已在队友的外地电脑验证网络连通。
  同步需要连接同一服务端和数据库；跨地域建议可信 VPN，参见 [部署说明](DEPLOYMENT.md)。
- 自动刷新是轮询，不是实时推送；编辑期间及部分保持选中项的页面会暂停，需要主动刷新。
- 商品测试数据的远程照片仍是示例素材，不是对应商品实拍。没有地址显示“暂无图片”，远程站点超时显示“图片暂不可用”；并未删除图片字段或把图片失败当作业务服务不可用。
- 没有逐个手工提交全部业务写按钮、检查所有 DPI/操作系统尺寸，也没有验证真实第三方付款或真实模型 API 对话。
- 商品评价候选当前仍使用首批已完成订单，长期大量订单的候选分页和“只显示未评价”体验仍需继续完善。
- 个别历史 DTO 仍缺少完整的人员展示信息（例如教室审批申请人、宿舍部分账单的人员摘要），后续应补齐姓名/学号关联，而非让用户猜内部编号。

以上边界明确保留；不能将“全部测试通过”理解为所有业务和所有外部环境都已经无缺陷。
